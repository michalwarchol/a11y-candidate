# Accessibility audit

| # | User impact | WCAG 2.1 | Recommended fix |
| --- | --- | --- | --- |
| 1 | On a dark canvas the page disappears: text is black, backgrounds are transparent, and the focus ring is invisible, so a keyboard user cannot see where focus is. Forcing a theme class still leaves the page background transparent, because `body` asks for a token that does not exist. | [1.4.3 Contrast (Minimum)](https://www.w3.org/TR/WCAG21/#contrast-minimum) (AA), [1.4.11 Non-text Contrast](https://www.w3.org/TR/WCAG21/#non-text-contrast) (AA), [2.4.7 Focus Visible](https://www.w3.org/TR/WCAG21/#focus-visible) (AA) | Put the light tokens on `:root`, or add `class="light"` on `<html>` before paint, and add `.dark` when `prefers-color-scheme: dark` matches. Point the `body` background at `--colors-surface-base`. Ship this with finding 11. |
| 2 | A keyboard user reaches only "Live only". "All sessions" and "Finished" are out of the tab order, and Enter and Space do nothing on the focused chip, so the heat list cannot be filtered. A screen reader is not told which chip is selected, and once colours paint the selection is colour alone. | [2.1.1 Keyboard](https://www.w3.org/TR/WCAG21/#keyboard) (A), [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG21/#name-role-value) (A), [1.4.1 Use of Color](https://www.w3.org/TR/WCAG21/#use-of-color) (A) | Replace the chips with `<button type="button">` elements in a group labelled "Filter sessions", every button in the tab order, `aria-pressed` on the selected one, and a non-colour selected cue (a checkmark, or a border that changes width). A radiogroup with `aria-checked` and a roving tabindex is an acceptable alternative. |
| 3 | Every status cell reads "—", so Qualified and Eliminated exist only as a background colour. A screen-reader user hears a dash, and in dark mode both backgrounds are `#282d3a`, so the cue disappears for everyone. The hidden second table repeats the caption and still has no standing. | [1.4.1 Use of Color](https://www.w3.org/TR/WCAG21/#use-of-color) (A), [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG21/#info-and-relationships) (A), [1.4.3 Contrast (Minimum)](https://www.w3.org/TR/WCAG21/#contrast-minimum) (AA) | Write `Qualified` or `Eliminated` in each status cell. A background may stay as a secondary cue if the two dark fills differ and clear 4.5:1 against the text. Delete the visually hidden table. |
| 4 | "Alpine skiing" and "Course: 58 gates, 180 m vertical drop" are painted into an SVG with `alt=""`. A screen reader skips them, and a user who needs a larger font or different spacing cannot restyle that sentence. | [1.1.1 Non-text Content](https://www.w3.org/TR/WCAG21/#non-text-content) (A), [1.4.5 Images of Text](https://www.w3.org/TR/WCAG21/#images-of-text) (AA) | Render those two sentences as real text in the same blue banner (`#063a5a`, white type). If a graphic remains, mark it decorative and do not let it be the only copy of the words. |
| 5 | The star is in the tab order with an empty name, so a screen reader announces an unlabeled button and voice control has no name to speak. Filling the star changes only an `aria-hidden` icon, so the pressed state is never announced. | [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG21/#name-role-value) (A), [1.1.1 Non-text Content](https://www.w3.org/TR/WCAG21/#non-text-content) (A) | Give the button an accessible name such as "Favourite" and `aria-pressed` that follows `isStarFilled`. Keep the icon `aria-hidden`. |
| 6 | The control that copies a link is named "Menu". A screen-reader or voice-control user has to activate an unknown control to learn that it copies a link. | [2.4.6 Headings and Labels](https://www.w3.org/TR/WCAG21/#headings-and-labels) (AA), [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG21/#name-role-value) (A) | Set `aria-label="Copy link"`. Keep "Link copied" in the status live region, and update the test that looks for "Menu". |
| 7 | The alerts layer is a dialog with no accessible name. Tab moves from Close into the page behind it, Escape does nothing once focus has left, and on close focus lands on `body` instead of "Manage alerts". | [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG21/#name-role-value) (A), [2.4.3 Focus Order](https://www.w3.org/TR/WCAG21/#focus-order) (A) | Name the dialog "Alert preferences" with `aria-labelledby` on the heading. Open a native `<dialog>` with `showModal()` so focus stays inside and Escape closes it, and return focus to "Manage alerts". `aria-modal` plus `inert` on the rest of the page is the equivalent if the overlay stays a `div`. |
| 8 | A screen reader is not told which panel Schedule, Results, or Medals controls. After activation the new view is only later in the page, so the user has to find it by reading on. | [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG21/#info-and-relationships) (A) | Give each panel an id. Set `aria-controls` on the tab and `role="tabpanel"` plus `aria-labelledby` on the section. Keep inactive panels in the DOM with `hidden`. |
| 9 | Athlete names are announced with no column header. Both sort buttons are named "Sort by rank", so speech that targets the visible word "Bib" misses that button, and neither header exposes whether the sort is ascending or descending. | [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG21/#info-and-relationships) (A), [2.5.3 Label in Name](https://www.w3.org/TR/WCAG21/#label-in-name) (A), [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG21/#name-role-value) (A) | Label the empty header "Athlete". Name the Bib button "Sort by bib" (Rank stays "Sort by rank"). Set `aria-sort` to `ascending` or `descending` on the active header and `none` on the other. |
| 10 | Three buttons are all named "Details", so a control list or voice control cannot tell Heat 1, Heat 2, and Heat 3 apart. The paragraph that opens is not programmatically tied to the button. | [2.4.6 Headings and Labels](https://www.w3.org/TR/WCAG21/#headings-and-labels) (AA), [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG21/#info-and-relationships) (A) | Keep the visible word "Details" and set an accessible name that still contains it, such as "Details for Heat 1". Give the paragraph a stable id, point `aria-controls` at it, and keep the paragraph in the DOM while collapsed. |
| 11 | Once a theme class paints the tokens, light borders are too faint to show where a control starts (1.41:1), the dark selected-tab label is 3.39:1, and white text on the dark brand hover fill is 2.78:1. | [1.4.11 Non-text Contrast](https://www.w3.org/TR/WCAG21/#non-text-contrast) (AA), [1.4.3 Contrast (Minimum)](https://www.w3.org/TR/WCAG21/#contrast-minimum) (AA) | Darken light `border.primary` and `border.secondary` to at least 3:1 against `surface.base`, and replace the translucent dark `border.secondary` with a solid colour at 3:1. Lighten dark `text.selected` and `text.link_hover` until they clear 4.5:1 on `#161923`. Darken dark `action.brand_hover`, or switch the hover label to a dark colour, until the label clears 4.5:1. Leave the pairs that already pass. |
| 12 | In dark mode Close has fill `#161923` and border `#5f6573` on the dialog fill `#3d4251`. The border is 1.72:1 against that fill and the button fill is 1.75:1, so the control disappears, and on hover the fill matches the dialog. The checkbox accent `#6e49ff` is 1.94:1 on the same surface. Dark `border.primary` on the filters and icon buttons is 3.00:1 against the page, the minimum for a 1 px line. | [1.4.11 Non-text Contrast](https://www.w3.org/TR/WCAG21/#non-text-contrast) (AA) | Lighten dark `border.primary` and `border.secondary` until they clear 3:1 against `surface.elevated` (`#3d4251`). Give the checkbox an accent and a 1 px outline that also clear 3:1 on that surface. |
| 13 | The view switcher is announced as tabs, but the tabs are links. Arrow, Home, and End do nothing, every tab is in the tab order, and Space scrolls the page. Below `64rem` the list is vertical while `aria-orientation` stays horizontal. The hrefs `#schedule`, `#results`, and `#medals` do not match any element on the page. | [2.1.1 Keyboard](https://www.w3.org/TR/WCAG21/#keyboard) (A), [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG21/#name-role-value) (A) | Use `<button type="button">` tabs with a roving tabindex. Arrow keys move and select, wrapping: Left/Right when the list is horizontal, Up/Down when it is vertical, plus Home and End. Set `aria-orientation="vertical"` below the `64rem` breakpoint. Ship this with finding 8. |
| 14 | On a narrow viewport the results table scrolls inside a container that is not in the tab order, so a keyboard user cannot bring the clipped columns into view. | [2.1.1 Keyboard](https://www.w3.org/TR/WCAG21/#keyboard) (A) | Make the overflow container a focusable region named by the table caption, and give it a visible focus ring. |
